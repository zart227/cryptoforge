## 1. Цель и ожидаемый результат

Добавить помощника исследователя, который анализирует результаты обучения торговой модели CryptoForge, предлагает проверяемые эксперименты и помогает расходовать ограниченный бюджет поиска эффективнее. Саму торговую модель обучает существующий численный pipeline. Дообучение LLM в этот план не входит.

Польза должна измеряться: при сопоставимых данных, вычислениях и числе попыток исследование с LLM должно находить более устойчивых кандидатов либо достигать сопоставимого качества быстрее и дешевле. Рост количества отчётов или убедительность объяснений не считаются улучшением.

Допустимый итог пилота: LLM не даёт измеримого преимущества; сохранить обычный поиск, помощника оставить только для объяснения результатов либо отключить.

План дополняет [основной план реализации](../IMPLEMENTATION_PLAN.md), [исследовательский план](PROFITABLE_STRATEGY_RESEARCH_PLAN.md) и [сверку R1–R16](IMPLEMENTATION_RECONCILIATION_20261014.md). Он не закрывает их открытые пункты и не даёт нового допуска к реальной торговле. Актуальное состояние реализации и runtime нужно повторно проверить перед работами.

## 2. На что опираться в текущем коде

Наличие модуля означает возможность повторного использования, но не подтверждает завершённую сквозную интеграцию.

- `src/cryptoforge/model_training.py`: основная модель `pure-python-logistic`, семь признаков `candle-v1`, обучение, метрики, артефакты и логика promotion.
- `src/cryptoforge/training_snapshot.py`: снимки данных и источников реализации для воспроизводимости.
- `src/cryptoforge/research_protocol.py`: исследовательский протокол.
- `src/cryptoforge/research_attempts.py`: SQLite-журнал попыток и постоянные бюджеты по семействам.
- `src/cryptoforge/research_evidence.py`: проверка зарегистрированных результатов.
- `src/cryptoforge/research_environment.py`: сведения о среде и версиях.
- `src/cryptoforge/walk_forward.py`, `walk_forward_selection.py`: временные проверки и выбор кандидатов; перед адаптацией сверить текущие контракты.
- `src/cryptoforge/model_registry.py`: загрузка моделей и проверка артефактов; новые семейства требуют отдельной проверки совместимости.
- `src/cryptoforge/night_research.py`: существующее ночное исследование; не считать его автоматически готовым оркестратором обучения.

## 3. Границы ответственности

LLM получает очищенный отчёт development-экспериментов и каталог разрешённых изменений. Возвращает структурированную гипотезу. Валидатор проверяет её, планировщик резервирует бюджет, worker обучает кандидата, evaluator считает метрики. Решение о дальнейшем допуске принимает код по зафиксированному протоколу.

- [ ] LLM не получает ключи Bybit, Supabase service role, содержимое `.env` и право отправлять ордера.
- [ ] В MVP LLM предлагает только конфигурации. После проверки MVP отдельный режим code experiments позволяет создавать патчи исследовательского Python и тестов в изолированной копии по правилам раздела 16; произвольный shell и SQL остаются вне этого режима.
- [ ] LLM не меняет риск-лимиты, разрешения, критерии допуска и бюджеты.
- [ ] Разрешены только версионированные параметры и признаки из каталога.
- [ ] Сбой помощника не влияет на управление открытой позицией и торговый runtime.
- [ ] Финальная оценка и решение реестра независимы от объяснения LLM.
