# Проверка объединённого чтения диагностических прогнозов

28 октября 2026. `RehearsalForecastReader` — изолированный read-only читатель
**двух закреплённых файлов репетиции**, не замена runtime-хранилищу. Каждый вызов
проверяет внешний SHA receipt, исходные размеры/hash файлов, отсутствие SQLite
sidecars, схему и counts; повторно проверяет hash после чтения. При пересечении
forecast ID, outcome ID или orphan outcome читатель отклоняет набор.

Поддержаны те же read-операции, что в `PrimaryForecastMemory`: `iter_rows`,
`rows`, `available_outcome`, `iter_labeled_asof` и `matured_batch`. Интерфейс
записи не реализован. Выбор версии соответствует исходному правилу последнего
доступного по времени outcome с максимальным ID. Для результатов поздних
исправлений нужен глобальный порядок ID; несовпадение ID само по себе не
доказывает правильность выдачи новых ID. Проверка во время завершения итерации
не может отозвать элементы, уже выданные при параллельном изменении файла;
поэтому использовать этот читатель для live-решений нельзя.

## Проверки

- На неизменном snapshot при as-of 28 октября 06:23:06 МСК совпали все **47 979**
  `iter_rows` и **47 700** `iter_labeled_asof`; по 6 выбранным forecast совпал
  `available_outcome`.
- На 24 октября 08:30 МСК совпали первые **100** `rows` и все **400** записей
  bounded `matured_batch` при заданном limit. Это проверка одинакового чтения
  сохранённого снимка, не доказательство исторической доступности данных.
- Synthetic тест записывает исправление для архивного forecast в активную часть
  с новым глобальным ID и сверяет read-поведение до/после; конфликты ID и orphan
  приводят к отказу. Механизм глобальной выдачи ID при этом не реализован.
- `tests/test_forecast_retention_reader.py` и совместимые тесты: **49 passed**,
  из них 8 новых. Полный suite проекта не запускался.
- Evidence `.local/state/forecast-composite-reader-audit-20261028/audit.json`,
  SHA-256 `8fbe0d1689fdce66dacd39df1c72b11222256219931364ae4ffbcb892a4043f2`;
  `batch-audit.json`, SHA-256
  `5b7ec4a23917857e214c9039420642deeb082e9bcc466b20d1ebf94ec6ef8998`.

## Остаётся

- [ ] Гарантировать глобальную последовательность ID с единой межпроцессной
  координацией и правильным поведением при сбоях, одновременной записи и rollback.
- [ ] Подтвердить full runtime call-site inventory и интеграцию всех зависимых
  сервисов, отчётов, ограничений времени и concurrency с новым storage contract.
- [ ] Проверить независимый backup, актуальность источника, прерывания, атомарный
  переход, откат и actual collection; снимок и две части лежат на одном диске.

Исследовательский читатель не запускает сервисы, не изменяет хранилище и не
создаёт метки реальных сделок. Выполненная проверка не подтверждает доходность.
