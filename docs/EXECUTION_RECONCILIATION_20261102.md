## Причины решений

Прочитаны 35 сохранённых approve_entry/approve_exit решений из настроенной базы
за тот же интервал; лимит выборки не достигнут. Сопоставление выполнено по
точному exchange orderId, паре и типу решения, без догадок по близкому времени.

- Причины выходов найдены для **20 из 30 ордеров бота**. Для 10 старых выходов
  точного контекста в выбранных данных нет; ещё 12 событий являются конверсиями.
- Точные причины входа покрывают **45.4723%** распределённой стоимости входов.
- Для MINA 8 октября найден net результат −2.6206% и exit_trend_down=True;
  сохранённый вход содержит entry_exit_conflict=True. Для NEAR 8 октября
  net −2.3950%, exit_trend_down=True. Это наблюдения, не доказательство
  причинности и не основание автоматически менять торговые правила.
- В шести закрывающих ордерах записанный эквивалент комиссии перекрыл
  неотрицательный результат до добавления комиссии. Комиссии уже включены в net.

Утраченные исторические причины нельзя восстановить из биржевых исполнений.
Существующий executor уже сохраняет новые отправленные решения под ключом
конкретного ордера с ignore-duplicates; этот механизм в данной работе не менялся.
Полная историческая атрибуция остаётся явно неполной, вместо выдуманных причин.

## Исправление процесса проверки

Прежние audit_execution_cache.py/review_execution_losses.py читали только старый
SQLite. Они не могли отвечать, были ли новые исполнения на бирже. Это ограничение
инструмента проверки; зависание runtime не подтверждено: исходный cursor журнала
уже обновлялся 2 ноября.

Добавлен scripts/reconcile_exchange_history.py: полный повторный запрос истории,
проверка неизменности исполнений, конверсий и wallet, точная атрибуция при наличии
сохранённых решений, исходные данные и SHA-256, копии использованного кода.
Исходный cache открыт только на чтение; нет публикации, уведомлений или ордеров.
Пустой ответ, потеря старых исполнений, изменение их содержания, несходящийся
wallet и неизвестные движения не получают статус reconciled. При обрыве
сохраняются неполные данные и статус incomplete, процесс завершается ошибкой.

scripts/capture_execution_decisions.py повторяемо читает решения из настроенной
базы для интервала сохранённого аудита. Запуск из корня репозитория:

```sh
.venv/bin/python scripts/reconcile_exchange_history.py --output .local/state/exchange-check-new
.venv/bin/python scripts/capture_execution_decisions.py --audit-dir .local/state/exchange-check-new
.venv/bin/python scripts/reconcile_exchange_history.py --output .local/state/exchange-attributed-new --decisions .local/state/exchange-check-new/decision-rows.json
```

более поздние hold/reject_entry перезаписывали строку с тем же ключом.
