# Read-only диагностика ёмкости forecast ledger

`src/cryptoforge/forecast_memory_health.py` и
`scripts/inspect_primary_forecast_health.py` отдельно показывают размер SQLite,
свободный диск и причины блокировки записи по явно заданным лимитам. Одновременно
они подсчитывают зрелые прогнозы без результата за последние 36 часов и более
старые незакрытые прогнозы. Это предотвращает смешение состояния «нет зрелых
прогнозов» с заполнением хранилища. Время доступности outcome проверяется на
выбранный момент; outcome из будущего не закрывает прогноз в прошлом. Данные о
записях с отсутствующим target time и будущим временем прогноза отображаются
отдельно. Проверка использует SQLite `mode=ro` и не создаёт cash labels или
торгового допуска.

Поле `forecasts_not_yet_mature` отдельно считает уже наблюдённые прогнозы,
целевой интервал которых ещё не закончился. Оно не включает прогнозы с будущим
временем наблюдения и помогает отличить ожидание созревания от отсутствующего
outcome для уже зрелого прогноза. Само число не подтверждает работу collector.

```bash
.venv/bin/python scripts/inspect_primary_forecast_health.py \
  --path .local/state/primary-forecast-memory.sqlite --env-file .env
```

Параметр `--env-file` считывает только
`CRYPTOFORGE_PRIMARY_FORECAST_MAXIMUM_MB`, не выводит другие настройки и даёт
значению файла приоритет над окружением, как у фонового executor. При отсутствии
ключа используется окружение или default 256 МиБ; поле
`capacity_configuration_source` указывает способ выбора. Без `--env-file`
используются только унаследованные переменные и default. Указание чужого файла
настроек не подтверждает фактическую конфигурацию работающей службы.

Срез 28 октября 06:11 МСК: `database_budget_reached` при размере 256 MiB;
47979 forecast и 47722 версии outcome; в обычном 36-часовом окне 0 незакрытых
зрелых прогнозов, за его пределами **279** зрелых прогнозов без записанного
результата. В этом срезе у прогнозов не обнаружено отсутствующего target time
или времени прогноза в будущем. Receipt —
`.local/state/forecast-snapshot-work-20261028/forecast-health.json`.

В 06:13 МСК выполнен отдельный bounded read-only поиск в local REST по
snapshot: 279 прогнозов относятся к 277 различным (pair, open_time) endpoint
на 50 парах. Найдены текущие candle rows для 226 endpoint и 226 прогнозов;
для 51 endpoint соответствующая строка не найдена. Это проверка наличия по
identity/time сейчас, без проверки OHLC/исторической доступности и без записи
outcome. Первоначальный receipt `old-endpoint-presence.json` содержит только
хеши ответов. Повторная проверка в 06:13 МСК сохранила 12 bounded запросов и
сырых ответов в `old-endpoints-presence-v2/`; отдельный offline replay сверил
snapshot, запросы, ответы, hashes и итог226/51. Это по-прежнему не проверка
цен и их исторической доступности.

Дальнейший bounded capture 06:14 МСК сохранил полные выбранные OHLCV и
локальные timestamps для 226 найденных endpoint. Независимый offline replay
проверил 12 пар request/response, identities и геометрию: все 226 имеют конечные
OHLCV с корректными low/high и неотрицательным volume. У 195 сохранённый
`updated_at` не раньше времени закрытия свечи, у **31 — раньше закрытия**;
их финальное значение этим срезом не подтверждено. Эти timestamps — поля текущей
базы, а не независимо подтверждённая история доступности. Receipt и raw data —
`old-endpoints-ohlc-v1/` в том же work-каталоге; outcome не записан.

Количество 279 не означает, что все endpoint ещё доступны или могут быть
восстановлены с прежним временем наблюдения. Реальные источники endpoint,
исторические версии и время их доступности нужно проверять отдельно; позднее
известное сохраняется как позднее наблюдение. Стандартный batch ограничен
36 часами. Эта CLI не установлена как служба и не восстанавливает запись.
Отсутствие capacity blockers само по себе не доказывает, что writer работает,
создаёт прогнозы или что модель прибыльна.

future outcome, пропущенную outcome table, отсутствие файла и запрет на alias.
Также повторно прошли проверки snapshot/restore и предыдущего forecast reader.
